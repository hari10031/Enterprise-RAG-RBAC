# How to run EKA v0.1

This guide covers four things. Commands are for Windows (PowerShell); Linux and macOS equivalents are noted where
they differ.

1. How to run the project, step by step.
2. What has been built.
3. What has been verified, and what still needs verifying.
4. What was installed or downloaded on this machine while building it.

---

## 1. What you are running

Four processes, one database:

| Process | What it does | Started with |
| --- | --- | --- |
| PostgreSQL 16 + pgvector | Stores everything: users, groups, documents, chunks, vectors, jobs, chats | a service you install |
| API (`eka.web.app`) | Login, questions (streamed), admin endpoints | `make api` |
| Worker (`eka.worker`) | Scans mapped folders, parses, chunks, embeds | `make worker` |
| Web app (`frontend/`) | The browser UI | `make web` |

Answers are generated by an LLM over an OpenAI-compatible API: Nebius, Google Gemini, NVIDIA NIM, or a local Ollama.
Embeddings and re-ranking run locally on the CPU.

## 3. Run it locally (step by step)

All commands run from the project folder:

```powershell
cd "M:\3-1\Enterpirse RAG -RBAC"
```

### 3.1 Install PostgreSQL and pgvector

1. Install PostgreSQL 16 with the EDB installer. Keep the default port 5432.
2. Install pgvector. There is no Windows installer, so build it once:
   1. Install "Visual Studio Build Tools" with the "Desktop development with C++" workload.
   2. Open **"x64 Native Tools Command Prompt for VS"** as Administrator, then run:

   ```bat
   set "PGROOT=C:\Program Files\PostgreSQL\18"
   cd %TEMP%
   git clone --branch v0.8.1 https://github.com/pgvector/pgvector.git
   cd pgvector
   nmake /F Makefile.win
   nmake /F Makefile.win install
   ```

   **Easier alternative:** if you install Docker Desktop, skip steps 1 and 2 and run only the database in Docker:
   `docker run -d --name eka-db -p 5432:5432 -e POSTGRES_PASSWORD=postgres pgvector/pgvector:pg16`

3. Create the database and its user. Open "SQL Shell (psql)" from the Start menu and log in as `postgres`:

   ```sql
   CREATE USER eka PASSWORD 'eka';
   CREATE DATABASE eka OWNER eka;
   \c eka
   CREATE EXTENSION vector;         -- must succeed; if it fails, pgvector is not installed
   SELECT extversion FROM pg_extension WHERE extname = 'vector';   -- want 0.8.0 or later
   ```

   The migration also runs `CREATE EXTENSION`. Running it here as the superuser avoids a permission error later,
   because the `eka` user is not a superuser.

4. For the tests, also create a throwaway database. **The tests wipe it.**

   ```sql
   CREATE DATABASE eka_test OWNER eka;
   \c eka_test
   CREATE EXTENSION vector;
   ```

### 3.2 Configure `.env`

```powershell
copy .env.example .env     # copy, don't rename: .env.example is the committed template
notepad .env
```

**Only one provider block may be active.** If a key such as `LLM_API_KEY` appears twice, the *first* value wins,
so a second uncommented block is silently ignored.

Set these values:

| Key | Value |
| --- | --- |
| `DATABASE_URL` | `postgresql://eka:eka@localhost:5432/eka` (change it if you used another password) |
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | Uncomment **one** provider block and paste your key. **Check the model id** in the provider's model list; the ids in the file are examples. |
| `COOKIE_SECURE` | `false` for local http. Must be `true` behind HTTPS. |
| `MODELS_DIR` | `./models` (already set) |

`.env` is git-ignored. Never commit it.

### 3.3 Install dependencies

```powershell
uv sync                        # Python packages into .venv
cd frontend; npm install; cd ..  # web packages into frontend\node_modules
```

(`make install` does both.)

### 3.4 Create the tables

```powershell
uv run --env-file .env alembic upgrade head
```

### 3.5 Create the first administrator

```powershell
uv run --env-file .env python -m eka.cli create-admin
```

It asks for an email, a name and a password of at least 12 characters. Running it again with the same email
resets that password.

### 3.6 Start the three processes (three terminals)

```powershell
# terminal 1: API on http://localhost:8000 (API docs: http://localhost:8000/api/docs)
uv run --env-file .env uvicorn eka.web.app:app --reload --port 8000

# terminal 2: ingestion worker
uv run --env-file .env python -m eka.worker

# terminal 3: web app on http://localhost:5173
cd frontend; npm run dev
```

Open **http://localhost:5173** and sign in with the admin account.

**First start is slow:** the first question or first indexed document downloads the embedding and re-ranker models
(about 150 MB) into `.\models`. After that they load from disk.

### 3.7 First use: set up access and content

Do this in the web app, as admin.

1. **People and groups:**
   1. Create groups, for example `hr`, `engineering` and `all-staff`.
   2. Add yourself to some of them. Admins only see what their groups allow, plus documents shared with no group.
   3. Add a few people and put them in groups.
2. **Shared folders:** map a folder, for example `D:\company\hr`, to the `hr` group. The **worker** must be able to
   read that path. Its files are indexed within seconds, then rechecked every 5 minutes.
3. **Documents:** or upload single files, choosing who can see each one. Leaving every group unticked means admins
   only.
4. Wait until the status says **Searchable**; the page refreshes itself while indexing.
5. Ask questions in **New question**. Sign in as a non-admin in another browser, or a private window, to see
   permissions working.

Supported files: PDF, DOCX, XLSX, PPTX, HTML, MD and TXT, up to 50 MB each. Scanned PDFs need OCR, which is off by
default. To turn it on, install Tesseract, run `uv sync --extra ocr` and set `OCR_ENABLED=true`.

### 3.8 Run the checks and tests

```powershell
uv run ruff check eka tests migrations
uv run mypy eka
cd frontend; npx tsc -b; cd ..
uv run pytest -q                                  # unit tests; the ACL matrix is skipped
```

**Access-control matrix: the most important test.** It needs the throwaway database from step 3.1:

```powershell
$env:TEST_DATABASE_URL = "postgresql://eka:eka@localhost:5432/eka_test"
uv run pytest -q                                  # now also runs tests/test_acl_matrix.py
Remove-Item Env:TEST_DATABASE_URL
```

It refuses to run on a database whose name does not contain `test`, because it drops and recreates the schema.
Expected result: `33 passed`.

(`make check` runs lint, types and tests together.)

### 3.9 Run the retrieval evaluation

1. Copy `eval\questions.example.jsonl` to `eval\questions.jsonl` and write your questions. The plan calls for 150:
   60 paraphrased, 40 identifiers, 30 multi-chunk or table questions, and 20 with no answer.
   - `relevant` is a snippet of text that the correct chunk contains.
   - Mark about 30 questions `"split": "final"`.
2. Run it:

```powershell
uv run --env-file .env python -m eka.eval eval\questions.jsonl --user you@company.test
```

It prints Recall@5, MRR@10 and not-found precision for dense only, keyword only, hybrid, and hybrid + re-rank. Add
`--final` **once**, at the end, for the numbers you report.

- **Chunk-size ablation:** set `CHUNK_TARGET_TOKENS=256` (or `600`) in `.env`, click Re-index on each document (or
  re-map the folder), then run the eval again.
- **Calibrating τ:** try several `RERANK_THRESHOLD` values. Pick the one that keeps not-found precision at or above
  0.85 without hurting Recall@5.

### 3.10 `make` shortcuts

If you install make, these save typing. Each runs the matching command above.

| Target | Runs |
| --- | --- |
| `make install` | `uv sync` and `npm install` |
| `make migrate` | the Alembic migration |
| `make create-admin` | the admin-creation prompt |
| `make api` / `make worker` / `make web` | the three processes |
| `make check` | lint, type checks and tests |
| `make test-acl` | the ACL matrix only |
| `make eval Q=eval\questions.jsonl U=you@company.test` | the evaluation |

## 4. Gemini notes (found while testing on 2026-09-29)

- **Free tier: 20 requests per day per model.** A first question costs 1 request; a follow-up costs 2 (rewrite +
  answer). Expect roughly 10-20 questions a day. For real use, enable billing on the Google AI project, or use
  another provider.
- **Model ids:**
  - `gemini-2.5-flash`: returns 404 for new users.
  - `gemini-3.8-flash`: returned 503 "high demand" on every attempt.
  - `gemini-flash-latest` and `gemini-flash-lite-latest`: both worked.
- **Thinking slows answers:**
  - `gemini-flash-latest` with `LLM_REASONING_EFFORT=none`: first words in about 2 s. Without it, 12-18 s.
  - `gemini-flash-lite-latest` answers in 1-3 s without the setting, and rejects `none` (use `low` or leave it unset).
- Gemini sends short answers in one or two pieces, so they appear all at once rather than word by word. That is the
  provider, not the app.

## 5. Troubleshooting

| Symptom | Cause and fix |
| --- | --- |
| `vector type not found in the database` | pgvector is not installed, or `CREATE EXTENSION vector` was not run in *this* database (step 3.1). |
| `permission denied to create extension "vector"` | Run `CREATE EXTENSION vector;` as `postgres` in that database, then rerun the migration. |
| `unrecognized configuration parameter "hnsw.iterative_scan"` | Should not happen: the code detects pgvector older than 0.8 and skips the setting. If it does, upgrade pgvector. |
| Login works but you are immediately signed out | `COOKIE_SECURE=true` over plain http. Set it to `false` locally. |
| "The language model's usage quota is used up" | Provider quota exhausted (Gemini free tier: 20 requests/day/model). Wait, change model, or enable billing. |
| "The language model is busy right now" | Provider returned 429/503 after 3 retries. Try again, or switch model. |
| "The language model rejected the request settings" | HTTP 400, usually an `LLM_REASONING_EFFORT` value that model does not support. |
| Code changes not taking effect | An old `uvicorn` still holds port 8000, and the new one logs `[Errno 10048]`. Find the old one with `Get-NetTCPConnection -LocalPort 8000 -State Listen` and stop that process. |
| Every answer ends in "The answer could not be generated" | Check the LLM settings in `.env`; the API terminal shows the provider's error. **System health** shows "Language model: Not working". |
| Every answer is "I could not find this…" | Either no documents are shared with your groups (the line under the question box shows your groups), or `RERANK_THRESHOLD` is too strict. |
| Documents stuck on "Waiting" | The worker is not running. **System health** shows "Ingestion worker: Not working". |
| Mapping a folder says "path is not a directory visible to the worker" | Use a path the machine running the API and worker can open. In Docker it must be under `/sources`. |
| `make` not recognised | Run the underlying command from section 3, or install make. |

## 6. What has been built

Everything in the implementation draft's v0.1 scope, phases 1 to 6:

| Phase | Delivered | Main files |
| --- | --- | --- |
| 1. Foundation | Schema and migration, local accounts (argon2id, lockout, 8-hour sessions), config, `create-admin`, lint and type checks, pre-commit, Docker Compose and nginx | `eka/core/*`, `migrations/`, `deploy/` |
| 2. Ingestion | 7 file parsers, file-type sniffing, folder scanner (size and mtime, then SHA-256), jobs queue with retries, parsing in a child process with a timeout | `eka/ingestion/*`, `eka/worker.py` |
| 3. Chunking and embedding | 400/480-token chunks with 60-token overlap, heading paths, repeated table headers, bge-small embeddings | `eka/indexing/*`, `eka/core/models.py` |
| 4. Retrieval and ACL | Vector and keyword search with the group filter in SQL, RRF fusion, cross-encoder re-rank, not-found gate, preview re-check | `eka/retrieval/search.py`, `eka/core/acl.py` |
| 5. Generation and API | OpenAI-compatible LLM client, follow-up rewriting, prompt, SSE streaming, citation checks, stop, rate limit, all endpoints, audit log | `eka/generation/llm.py`, `eka/web/*` |
| 6. Web app and eval | React chat with source chips and source panel, admin pages, eval harness and ablations | `frontend/`, `eka/eval.py` |

Differences from the draft are listed in `README.md`. The important one: with a hosted LLM, questions and the
passages retrieved for them are sent to that provider.

## 7. Docker deployment (later, on the target host)

```bash
cp .env.example .env            # set the LLM keys; COOKIE_SECURE=true
mkcert -install && mkcert -cert-file deploy/certs/eka.pem -key-file deploy/certs/eka-key.pem eka.local
docker compose -f deploy/docker-compose.yml --profile setup run --rm models   # one-off model download
docker compose -f deploy/docker-compose.yml up -d --build
docker compose -f deploy/docker-compose.yml exec api python -m eka.cli create-admin
```

- Watched folders go under `./sources` on the host (or set `SOURCES_DIR`). Map them in the UI as `/sources/...`.
- **Not yet tested:** the Compose stack has never been run, because Docker is not installed here. See section 8.

### Verified during the build

| Check | How | Result |
| --- | --- | --- |
| Lint and types | ruff, mypy, `tsc -b` | clean |
| Unit tests | chunker, parsers (all 7 formats), RRF, citations, passwords, eval metrics | pass |
| **ACL matrix** | Real PostgreSQL 16 through the full pipeline (scanner, worker, SQL, API), with fake models and a fake LLM that echoes its whole prompt | 8/8 pass: no canary leaks through answers, citations, previews or rewritten questions; revocation and folder remap apply on the next query |
| Migration | `alembic upgrade`, `downgrade`, `upgrade` again | works |
| Real local models | bge-small embeddings, tokenizer (counts beyond 512), MiniLM re-ranker | work; a relevant passage scored -0.5, an irrelevant one -11.3 |
| End-to-end in a browser | Full stack plus a **stub** LLM server in Chrome | login, streaming, source chips, source panel, not-found, admin pages, mobile width, no console errors |
| Eval harness | Example set against the seeded corpus | runs and prints the table |

**Caveat:** that PostgreSQL was a throwaway one (from the `pgserver` Python package) with **pgvector 0.6.2**, not
0.8. The `iterative_scan` path for 0.8+ has not been exercised.

### Not verified: please check these

1. **A real LLM provider: done on 2026-09-29 with Gemini.** Verified: cited answers, follow-up rewriting, the source
   preview, the not-found gate, the ACL between two users, and the provider error messages. Re-check if you change
   provider or model.

   Also check that the model id in `.env` is valid for your provider. Gemini's and NIM's OpenAI-compatible endpoints
   have small differences that were not exercised.
2. **Native PostgreSQL + pgvector 0.8 on Windows.** Run the ACL matrix (section 3.8) against it and expect
   `33 passed`.
3. **Answer quality with your model.** Check that citations point at the right passages. Check that "not found"
   appears for questions your documents cannot answer, rather than an invented answer.
4. **The re-rank threshold τ (`RERANK_THRESHOLD`).** -4.0 is a placeholder. Calibrate it with the eval (3.9).
5. **Real documents.** Especially scanned or unusual PDFs, large Excel files, and PowerPoint files with tables. The
   doc's revisit trigger is more than 2% of files failing (status "Failed").
6. **Latency targets.** p95 time to first word of 5 s or less, and full answer of 30 s or less, with about 3 people
   asking at once. **System health** shows both.
7. **Docker deployment** (section 6), on a machine with Docker.
8. **A network share (SMB)** as a watched folder, if you plan to use one.
9. **Security review** before real data: the account lockout, that the cookie is `Secure` behind HTTPS, and nginx
   TLS headers.

## 9. What was installed on this machine while building

Nothing was installed system-wide. There are no new services, no PATH or registry changes, and no admin rights were
used.

| What | Where | Size, approx. | Remove with |
| --- | --- | --- | --- |
| Python packages for the project | `.venv\` in the project folder | a few hundred MB | delete `.venv` |
| Web packages | `frontend\node_modules\` | about 100 MB | delete `node_modules` |
| Web build output | `frontend\dist\` | small | delete `dist` |
| Embedding and re-ranker model weights (fastembed) | `%TEMP%\fastembed_cache` (before `MODELS_DIR` was added to `.env.example`) | about 150 MB | delete that folder; they re-download to `.\models` on next use |
| `pgserver` (throwaway PostgreSQL for testing) | uv's package cache, in a temporary environment, not in the project | about 100 MB | `uv cache clean pgserver` |
| Throwaway database files (stopped) | Claude's session scratchpad under `%TEMP%\claude\...` | small | delete that temp folder |
| uv's package download cache | `%LOCALAPPDATA%\uv\cache` | shared by all uv projects | `uv cache prune` |

Already present, **not** installed by this work: Python 3.12, uv, Node.js, npm, and the uv-managed Python 3.13 (dated
January 2026). The project's `.venv` uses Python 3.13.11.

Processes started for testing (stub LLM, API, worker, Vite, throwaway PostgreSQL) were all stopped afterwards.

**Git:** nothing has been committed. All files are untracked in a repository with no commits yet.
